\begin{abstract}
Graph language models (GLMs) answer questions from soft graph tokens, where the graph is assumed to be fixed.
In dialogue, users revise the world, and graph tokens computed before a revision become stale.
We build a synthetic benchmark of multi-turn sessions (4,455 turns per split) in which each turn is a revision followed by a question, and 36\% of test turns change the answer.
GraphModi converts each revision into a typed edit program, applies it to an explicit graph, re-encodes the result, and answers from the new graph tokens with a frozen Llama-3.1-8B-Instruct that never sees the revision text.
With a GraphToken-style reader (three seeds), re-encoding scores 53.7\% on test against 41.3\% for stale tokens plus the revision text, 32.4\% for a shuffled graph, 34.7\% for a trained soft prompt that reads the revisions, and 28.4\% for zero-shot Llama reading the serialized graph.
Model-written edits are execution-correct on 96.6\% of turns and cost 0.2 points.
The gain is largest on answer-changing turns (51.2\% vs.\ 25.2\% with stale tokens), but learned local classifiers reach 67--70\% on the structural tasks, and on turns that no local rule solves every model is near 21\%: the reader tracks updates through local features, not multi-hop reasoning.
A TEA-style reader, whose GNN is pretrained with TEA-GLM's contrastive objective and then frozen, reaches @@sessions.all.tea.oracle_updated_graph.all.mean@@\%; linear probes show that this pretraining removes station status from the node embeddings.
\end{abstract}

\section{Introduction}
\label{sec:intro}

Graph language models (GLMs) map a graph through a GNN into soft tokens that a frozen or adapted language model can attend to~\cite{perozzi2024graphtoken,wang2024teaglm,he2024gretriever,plenz-frank-2024-graph}.
All such work assumes the graph does not change.
Real graphs are updated, and in dialogue a user may report changes as they happen.
After such a change, graph tokens computed from the old graph describe a world that no longer exists.

One way to handle this is to keep the updates in the text context and rely on the language model to track them.
Dynamic-graph QA benchmarks study this setting with graphs described in text~\cite{comrie2025dygraphqa}.
Another is to update stored knowledge directly, but parametric knowledge editors can recall a new fact and fail to propagate its effects~\cite{zhong-etal-2023-mquake}.
GraphModi keeps state external: an edit program is applied to an explicit graph, the graph is re-encoded, and the QA call receives only the new graph tokens and the question, never the revision text.
This lets us score writing (did the edit land?) separately from reading (can the model answer from the new tokens?).

\paragraph{Research questions.}
\begin{description}[leftmargin=0.5em,style=nextline,font=\normalfont\itshape,itemsep=1pt]
  \item RQ1: Can a frozen LLM emit executable edit programs from a few-shot prompt, and what do its errors cost downstream?
  \item RQ2: Does answering from re-encoded tokens beat stale $G_0$ tokens and text-history controls as turns accumulate, especially on answer-changing turns?
  \item RQ3: Do graph tokens carry information beyond graph-blind baselines, and beyond what local features of the queried stations give?
\end{description}

\paragraph{Contributions.}
\begin{description}[leftmargin=0.5em,style=nextline,font=\normalfont\itshape,itemsep=1pt]
  \item i) A formulation of multi-turn GLM updating with an edit language and executor, which separates write accuracy from read accuracy.
  \item ii) A multi-turn benchmark across graph size, density, session length, and task, with paired conditions that isolate stale tokens, text history, graph-blind and zero-shot text baselines, and learned local-shortcut ceilings.
  \item iii) Evidence over three seeds that re-encoding beats stale tokens and every text channel, by the widest margin on answer-changing turns, and that model-written edits cost almost nothing.
  \item iv) A diagnosis of what the readers learn: GraphToken-style reading stays within local features, and TEA-style contrastive pretraining discards the node status that updates change.
\end{description}

\section{Related Work}
\label{sec:lit}

\paragraph{Graphs as text.}
A graph can be written in natural language so that an LLM attempts structural reasoning with no GNN~\cite{wang2023nlgraph,fatemi2024talk}.
\citet{fatemi2024talk} show that accuracy varies substantially with how the graph is encoded as text, and \citet{wang2023nlgraph} find that LLM graph reasoning can rely on spurious patterns instead of the actual relationships in the graph.
We evaluate the serialized graph as a zero-shot baseline, and several of our controls use text history.

\paragraph{Soft graph tokens.}
GraphToken learns a graph encoder end-to-end through the language-modelling objective with a frozen LLM~\cite{perozzi2024graphtoken}.
TEA-GLM pretrains a GNN with instance-wise graph contrastive learning~\cite{zhu2020grace} plus a feature-wise contrastive loss on the principal components of the LLM's token embeddings, freezes it, and then trains a linear projector onto a fixed number of tokens~\cite{wang2024teaglm}.
G-Retriever and the graph language models of \citet{plenz-frank-2024-graph} also couple graph representations with frozen or lightly adapted LMs~\cite{he2024gretriever}.
All of them evaluate QA against a graph supplied once per query and do not explore how a revision should modify the encoded graph.
We build TEA-style and GraphToken-style readers rather than claim exact reproductions, since our readouts, tasks, and training data differ from the originals.

\paragraph{Do GLMs use the graph?}
CLEGR shows that a graph-blind soft-prompted LLM can rival full GLMs on metro reasoning, and proposes a shuffled-graph control to detect this~\cite{petkar2026clegr}.
\citet{liu2024softpromptgraph} ask the same question for soft prompting on graph learning tasks.
We adopt the soft-prompt baseline and the shuffled-graph control, and treat parity with either as evidence against a graph-reading claim.

\paragraph{Dynamic graphs and stateful dialogue.}
DyGraphQA evaluates LLMs on graphs that change through additions and deletions described as text or structured data~\cite{comrie2025dygraphqa}.
MQuAKE shows that knowledge edits made inside model parameters often fail to propagate to multi-hop questions~\cite{zhong-etal-2023-mquake}.
SKG-Eval stores conversational claims in an incremental knowledge graph to detect cross-turn conflicts~\cite{shil2026skgeval}.

\section{Problem Formulation}
\label{sec:problem}

Consider a transit assistant that initially knows two routes between a pair of stations.
The user then says that one station is closed.
The text decoder sees the correction, but a frozen graph representation still describes the station as open, so the model is given two versions of the world.
Keeping the full conversation in the prompt may help, but it does not repair the graph that the GNN encodes, and it makes the system depend on implicit state tracking by the language model.
Updating needs \emph{writing} (mapping a revision to a graph change) and \emph{reading} (answering from re-computed graph tokens), which we score separately on turns where the edit changes the answer and where it does not.

\paragraph{Graph and session.}
Let $G=(V,E,a,\rho)$ be an undirected attributed metro graph.
Node attributes include line, accessibility, architecture, cleanliness, music, size, and $\mathrm{status}\in\{\mathrm{open},\mathrm{closed}\}$; edge relations $\rho$ are $\mathrm{track}$ or $\mathrm{transfer}$.
A session is $S=(G_0,(r_t,q_t)_{t=1}^{T})$, where $r_t$ is a natural-language revision and $q_t$ a question.

\paragraph{Edit language.}
An edit program is a semicolon-separated list of at most three operations terminated by \texttt{END}.
Legal operators are \texttt{SET NODE} (set station status), \texttt{ADD EDGE}, \texttt{DEL EDGE}, and \texttt{NOOP}.
Gold programs $P_t^\star$ induce
\begin{equation}
G_t=\mathrm{Apply}(G_{t-1},P_t^\star).
\end{equation}
Gold and stale answers are $a_t^\star=\mathrm{Solve}(G_t,q_t)$ and $\tilde{a}_t=\mathrm{Solve}(G_{t-1},q_t)$; the answer-changing set is $\mathcal{C}=\{t:a_t^\star\neq\tilde{a}_t\}$.

\paragraph{GraphModi.}
At each turn the system computes
\begin{align}
\hat{P}_t &= f_{\mathrm{edit}}(r_t), \\
\hat{G}_t &= \mathrm{Apply}(\hat{G}_{t-1},\hat{P}_t), \\
Z_t &= W\cdot\rho\bigl(\mathrm{GNN}(X(\hat{G}_t)),q_t\bigr)\in\mathbb{R}^{K\times d}, \\
\hat{a}_t &= \mathrm{LLM}\bigl(\mathrm{prompt}(q_t),\,Z_t\bigr).
\end{align}
Edit prediction uses the revision text only; the graph is used for node-name resolution.
The revision $r_t$ is withheld from the QA call, so a correct answer after an edit has to come from the updated tokens.
The LLM stays frozen; the GNN and projector are trained by minimizing $-\log p(a\mid q,Z(G,q))$ on static QA pairs.

\paragraph{Metrics.}
We report exact-match accuracy overall, on $\mathcal{C}$, and on its complement, plus execution-equivalent edit accuracy for the write path.
Answers are parsed from the first line of the generation.
Confidence intervals are 95\% session-clustered bootstrap intervals, and differences between conditions are paired by turn and clustered by session.
Two reference points are not models.
The \emph{per-task majority} predictor answers each task's most common gold answer, and the \emph{stale answer} returns $\tilde{a}_t$, the answer before the turn's edit; it is an upper reference for a system that ignores edits.

\section{Methodology}
\label{sec:method}

\paragraph{Write path.}
A few-shot prompt (output format, a NOOP example, multi-operation outputs separated by `\texttt{;}' and ended by `\texttt{END}') makes the frozen LLM emit an edit program with greedy decoding.
Station labels, including multi-word names, are mapped to node IDs and operations are applied as given; invalid operations are skipped, so an edit error propagates to later turns.
Edit accuracy is the fraction of turns where the predicted program yields the same graph as the gold program.

\paragraph{Read path.}
Nodes are featurized by a frozen \texttt{bert-base-uncased} encoder~\cite{devlin-etal-2019-bert} (768-d, mean-pooled over ``\texttt{label: attr=val, \ldots}'', including status) and passed through a 3-layer GraphSAGE~\cite{hamilton2017inductive} with sum aggregation, layer normalization, no dropout, and widths 768$\to$1024$\to$1024$\to$4096.
The output width equals the LLM hidden size, which TEA-GLM pretraining requires; all graph readers share this encoder shape.
The readout is task-conditional: the source and target node embeddings when the question names them, and the mean pool otherwise.
It is concatenated with a hop-radius scalar and a task one-hot (12{,}305-d) and linearly projected to $K{=}10$ tokens of width 4096.
As in CLEGR, the text of the queried node(s), $W(f_i)$, is added to the question, with station status removed so that it can only come from the graph.
The LLM is a frozen Llama-3.1-8B-Instruct in bfloat16~\cite{llama3modelcard}, and every prompt is \texttt{Question: \{q\}\textbackslash nAnswer:} followed by the graph tokens.

\paragraph{Readers.}
\emph{GraphToken-style}: the GNN starts from random weights and is trained jointly with the projector.
\emph{TEA-style}: two stages. The GNN is first pretrained self-supervised with TEA-GLM's objective, as in the authors' released code: two views of each batch (edges dropped with probability 0.3 and 0.4, node-feature dimensions masked with probability 0 and 0.1), a GRACE instance-wise loss~\cite{zhu2020grace} through a two-layer projection head, plus a feature-wise contrastive loss on the node embeddings projected onto the top 1{,}000 principal components of Llama's token-embedding table ($\tau{=}0.4$, Adam lr $2{\times}10^{-3}$, dropout 0.5, up to 70 epochs with patience 10).
The GNN is then frozen and only the projector is trained.
Two ablations sit between them: a \emph{warm start} that initializes the GraphToken-style GNN from the TEA-GLM-pretrained one and trains it jointly, and a \emph{frozen random GNN} that trains only the projector on a seeded random GNN.
The \emph{soft prompt} learns $10\times4096$ prompt tokens with no GNN.

\paragraph{Training.}
All readers train for one epoch on 24{,}000 static QA pairs (18{,}000 static items plus 6{,}000 before/after pairs around a random edit) with AdamW (weight decay $10^{-4}$), effective batch 24, bf16, a cosine schedule with 200 warmup steps, and validation loss every 100 steps on 1{,}000 validation items; the checkpoint with the lowest validation loss is evaluated.
For every reader, the projector learning rate is chosen from $\{10^{-3},3{\times}10^{-4},10^{-4}\}$ by validation loss on seed 42, and all four chose $10^{-4}$; jointly trained GNNs use $10^{-4}$ (Appendix~\ref{app:hparams}).
GraphToken-style and TEA-style use seeds 42, 43, and 44; the ablations and the soft prompt use seed 42.
No model is trained on multi-turn sessions; all must generalize from static examples to graph states created at evaluation time.

\paragraph{Benchmark.}
Graphs are a ring core with pendant chains (some closing into triangles), 12--22 stations, mean degree 2.8/3.8/5.0 for the sparse, medium, and dense settings, and diameter capped at 7/6/5.
Nodes carry CLEGR-like attributes and fictional two-word station names.
Static QA covers eleven task families (Appendix~\ref{app:task-families}) with per-task answer quotas, so yes/no tasks are balanced.
The multi-turn grid crosses 11 node counts, 4 session lengths $\{1,2,4,8\}$, 3 densities, and 9 tasks: 1{,}188 sessions and 4{,}455 turns per split.
Revisions use three paraphrase families; the \texttt{notice} family is held out of the few-shot edit prompt.
A per-split quota makes 36.4\% of test turns answer-changing (the stale answer scores 63.6\%), 16.7\% of turns are NOOP, and no session contains a net-no-op, cancelled, or disconnecting edit.
Every stored label and edit was re-derived by independent solvers (0 mismatches), and a leak audit of the question text is clean.

\paragraph{Shortcut ceilings.}
Because the benchmark is synthetic, we measure how far local features of the queried stations go.
A per-task gradient-boosted classifier fit on static train with one-hop features (degree, status, leaf and closed neighbours, smallest neighbour degree, hop radius, graph size) reaches 63.4\% on static test and 61.9\% on the updated test-session graphs over the non-attribute tasks; adding two-hop features (stations, leaves and closed stations at two hops, triangles, neighbour degrees, common neighbours; no distances) reaches 70.1\% and 67.0\%.
A 3-layer GNN sees all of these features, so accuracy near these ceilings shows local reading, not multi-hop reasoning.
The 1{,}052 test turns that both classifiers get wrong form the \emph{local-wrong} slice.
Text-only lookups fit on validation sessions reach 36.6\% from the revision text alone and 78.7\% from the stale answer plus the revision text, because 50\% of turns ask about an edited station; the \emph{changed-and-unmentioned} slice (359 answer-changing turns whose question does not name an edited station) removes that route.

Each multi-turn session is evaluated under the paired conditions in Table~\ref{tab:conditions-def}.
They differ in which graph the tokens encode and in what text the model sees.
The oracle condition re-encodes the gold graph and the predicted condition re-encodes the graph built from the model's own edits, so the gap between them is the cost of edit errors.

\subsection{Write path}
\label{sec:write}

The \texttt{predicted\_updated\_graph} condition applies the model's own edit programs and re-encodes the result, and it answers RQ1.
The frozen LLM writes an execution-equivalent program on 96.6\% of test turns, and the graph state built from its own edits is exactly right on 91.1\% of turns, since an error persists for the rest of a session.
NOOP turns are always correct and status and deletion edits are above 97\%; the weakest operation is a lone \texttt{ADD EDGE} at 79.9\%.
On the \texttt{notice} paraphrase family, held out of the few-shot prompt, edit accuracy is 91.5\% against 98.9--99.3\% for the other two.
These errors cost 0.2 points for GraphToken-style (53.5\% vs.\ 53.7\%; paired CI $-0.1$ to 0.5) and at most @@write_cost_max@@ points for every reader, and the predicted and oracle rows agree within 1.3 points by session length, change status, density, and task (Tables~\ref{tab:length}--\ref{tab:pertask}).

\section{Inferences}
\label{sec:discussion}

\paragraph{Graph tokens encode the specific, current graph.}
Re-encoded GraphToken-style tokens beat a shuffled graph by 21.8 points, a graph-blind soft prompt by 19--21 points with or without the revision text, and zero-shot Llama reading the serialized graph by 25 points, at every density and session length and on all three seeds.
A model that ignored the tokens would score the same under all of these conditions, so the tokens carry session-specific information (RQ3).

\paragraph{Staleness hurts exactly where an edit matters.}
On answer-changing turns stale tokens fall to 25.2\%, below the per-task majority, while re-encoded tokens keep 51.2\%; on unchanged turns the two are within 5 points.
The gap survives on changed turns whose question does not name the edited station (35.8\% vs.\ 26.1\%), where no text lookup helps (RQ2).

\paragraph{The gain comes from re-encoding, not from text history.}
Adding the revision text to stale tokens does not help: \texttt{frozen\_graph\_history} and \texttt{structure\_only} are both 41.3\%.
Text channels that see the full history do not catch up either: the soft prompt reaches 34.7\%, and zero-shot Llama with the initial graph and every revision in context reaches 29.9\%.
Updating the graph and re-reading it is what recovers the answer.

\paragraph{The write path is not the bottleneck.}
Model-written edits are 96.6\% execution-correct and cost 0.2 points (RQ1), but revisions are templated, so this likely overstates the write path on free-form dialogue.

\paragraph{The reader is local.}
GraphToken-style accuracy stays at or below learned local ceilings on the structural tasks, and on turns that no local rule solves it is no better than a shuffled graph (20.9\% vs.\ 20.1\%).
The benchmark rewards tracking local facts that updates change; it does not yet show that soft graph tokens support multi-hop reasoning.

\section*{Limitations}

The benchmark is synthetic and its revisions follow templates, so edit accuracy likely overstates performance on free-form dialogue.
GraphToken-style and TEA-style use three seeds; the warm start, the random GNN, and the soft prompt use one.
Every reader trains for one epoch on static QA, and the projector learning rate was chosen on validation loss after a first round of runs at $10^{-3}$, in which the readers built on a frozen or pretrained GNN had not converged.
Learned local classifiers reach 67--70\% on the structural tasks, so absolute accuracy on this benchmark mostly measures local reading.

\section{Task Families}
\label{app:task-families}

Static QA covers eleven task families; the multi-turn grid uses the first nine.
Every answer is computed by a symbolic solver on the current graph, and yes/no tasks are balanced.
In the definitions below, A and B are station names.
\begin{itemize}
  \item \textbf{Edge existence}: is there a direct edge between A and B?
  \item \textbf{Reachability}: can B be reached from A using open stations only?
  \item \textbf{Constrained reachability}: can B be reached from A without passing through a station of a given class (no disabled access, no rail, or dirty)?
  \item \textbf{Cycle membership}: is A part of any cycle? Asked only about degree-2 stations, so degree alone does not answer it.
  \item \textbf{Node degree}: how many stations are directly connected to A?
  \item \textbf{Filtered neighbour count}: how many direct neighbours of A have a given attribute value?
  \item \textbf{Shortest path}: how many stations, including both endpoints, lie on the shortest open path from A to B (or \texttt{unreachable})?
  \item \textbf{Within-hops count}: how many other stations within two hops of A have a given attribute value?
  \item \textbf{Most common attribute within hops}: what is the most common value of an attribute among the stations within two hops of A, including A itself? Only queries with a unique mode are kept.
  \item \textbf{Attribute lookup}: what is the value of one of A's attributes? The answer is an open categorical value.
  \item \textbf{Attribute check}: does A have a given attribute value?
\end{itemize}
The last two are CLEGR's Facts tasks.
For them, and for the most-common-attribute task, the queried attribute is withheld from $W(f_i)$, so the answer has to come from the graph tokens.
The Facts tasks are static only: revisions set station status or add and remove edges, so they never change a node attribute.
Reachability and shortest-path questions use open endpoints only, and the cycle task is asked only at degree-2 stations; under these filters a degree-and-status lookup rule reaches 41.0\% on seven tasks, and the rule ``a neighbour of a leaf is not on a cycle'' reaches 79\% on cycle membership.

\paragraph{Static accuracy by task family.}
Figures~\ref{fig:static-tasks-gt} and~\ref{fig:static-tasks-tea} break Table~\ref{tab:static} down by task family against the soft prompt and the learned local ceiling.
GraphToken-style is strongest on node degree (97.5\%), cycle membership (79.0\%), reachability (65.2\%), and edge existence (61.7\%), and below the local ceiling on each.
On the attribute tasks it stays close to the soft prompt: attribute lookup 29.0\% (soft prompt 25.8\%), most common attribute 27.9\% (26.5\%), and attribute check 49.9\% (50.5\% majority), so the tokens carry little beyond the node status and structure that the training signal emphasizes.
