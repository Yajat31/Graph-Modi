# metro_v4 generator v4.1 benchmark note (2026-10-30)

Frozen benchmark for the paper runs. Data live in `datasets/metro_v4_1/` (graph metadata carries
`generator_version: v4.1`).

## Sampler design choices (`src/graph_modi/data/v4.py`)

| Risk | Design |
|---|---|
| Few session turns change the answer, so the stale answer scores high | Per-split quota (`TARGET_CHANGED_SHARE = 0.45`) prefers answer-changing queries; non-NOOP turns widen the candidate pool until one exists (`_session_pool_v4`). For yes/no tasks the quota takes the rarer answer, so yes-rates stay near 0.5 |
| Cycle: "neighbour of a leaf → no" solves degree-2 cycle items in tree-like chains | Pendant chains of length ≥ 2 end in a triangle with probability `LOOP_CHAIN_PROB = 0.6`, so chain interiors can lie on cycles |
| A cycle hop tag that depends on the answer leaks the label | Cycle items are always `global` |
| Counterfactual "before" items could violate the test filters (closed endpoints, non-degree-2 cycle nodes) | `_v4_eligible` is applied to the before graph too |

Edits use three paraphrase families (`direct`, `service`, `notice`); `notice` is held out of the
few-shot edit prompt. About 17% of session turns are NOOP.

cycle reasoning.

## Learned local shortcut (`scripts/analyze_v4.py --shortcut-only`)

The gate ceilings above are fixed lookup rules. A gradient-boosted classifier per task, fit on
static train with only one-hop features of the queried stations (degree, status, number of leaf
neighbours, smallest neighbour degree, closed neighbours, plus hop radius, graph size and closed
count), is much stronger. Results: `documents/experiments/results/v4_1-analysis/shortcut_ceilings.json`.

| Task | static test | test sessions (updated graph) |
|---|---|---|
| node_degree | 100.0 | 100.0 |
| cycle_membership | 89.9 | 82.2 |
| reachability | 87.1 | 83.0 |
| edge_exists | 84.6 | 81.4 |
| constrained_reachability | 62.4 | 60.4 |
| shortest_path | 41.2 | 37.4 |
| filtered_neighbor_count | 25.8 | 33.7 |
| within_hops_count | 16.2 | 16.8 |
| **non-attribute overall** | **63.4** | **61.9** |

What this means for the paper:

- A 3-layer GNN sees these features, so reaching ~63% on non-attribute tasks is consistent with a
  **local degree/status reader** and is not evidence of multi-hop reasoning. Reachability, cycle and
  edge existence are mostly solvable locally, and the generator is frozen.
- The one-hop classifier is not the local ceiling. Adding two-hop features (nodes, leaves and closed stations at two hops, triangles, neighbour
  degrees, common neighbours; no distances) gives 70.1% static / 67.0% sessions (cycle 95.7 / 88.1,
  reachability 92.4 / 91.3, edge existence 95.2 / 91.5). The pre-registered evidence slice is
  therefore **local-wrong** (wrong under both classifiers, 1,052 test turns), and text-only lookups
  (36.6%, or 78.7% with the stale answer) are reported as baselines. `hop_depth` still encodes the
  answer for reachability (90.9% from the tag alone) and bins shortest path; it is metadata only,
  so it is not a model input, but it must not be used as a slice for those tasks.
- The one-hop **shortcut-wrong slice** (1,510 of 3,960 non-attribute test turns) is reported too.
- Counting tasks (`within_hops_count`, `filtered_neighbor_count`, `shortest_path`) are not locally
  solvable and separate a structure reader from a degree reader.

Test-session slice sizes: answer-changing 1,622; `mentions_edit == false` 2,220; both 359;
shortcut-wrong 1,510; local-wrong 1,052; 1,485 per paraphrase family.
