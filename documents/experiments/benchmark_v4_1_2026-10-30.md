# metro_v4 generator v4.1 benchmark note (2026-10-30)

Frozen benchmark for the paper runs. Same distribution name (`metro_v4`) and task set as v4.0
([benchmark_v4_2026-10-25.md](benchmark_v4_2026-10-25.md)), but the data differ: **do not mix v4.0
and v4.1 numbers.** Data live in `datasets/metro_v4_1/` (graph metadata carries
`generator_version: v4.1`).

## What changed from v4.0 (`src/graph_modi/data/v4.py`)

| Problem in v4.0 | v4.1 change |
|---|---|
| Only 14.6% of session turns changed the answer, so the stale answer scored 85% | Per-split quota (`TARGET_CHANGED_SHARE = 0.45`) prefers answer-changing queries; non-NOOP turns widen the candidate pool until one exists (`_session_pool_v4`). For yes/no tasks the quota takes the rarer answer, so yes-rates stay near 0.5 |
| Cycle: "neighbour of a leaf → no" solved ~95% of degree-2 cycle items | Pendant chains of length ≥ 2 end in a triangle with probability `LOOP_CHAIN_PROB = 0.6`, so chain interiors can lie on cycles |
| Cycle hop tag was `mid` iff the answer was yes (label leak through the hop field) | Cycle items are always `global` |
| Counterfactual "before" items could violate the v4 test filters (closed endpoints, non-degree-2 cycle nodes) | `_v4_eligible` is applied to the before graph too |

Everything else (labels, write path, NOOP rate, paraphrase families, the held-out `notice` family) is
unchanged from v4.0.

Stale-answer baseline on test sessions: 63.6% (was ~85%). Per-task majority answer: 32.3%.
Answer-changing share by task (test; v4.0 had edge existence, constrained reachability and
most-common-attribute under 4%): shortest path 0.455, node degree / filtered count / within-hops
0.451, edge existence 0.408, most-common attribute 0.291, reachability 0.273, constrained
reachability 0.259, cycle 0.240.

**Warnings (accepted trade-off).** `mention_near_chance`: on edit turns, 0.588 (val) and 0.602
(test) of queries mention an edited station, against a chance rate of about 0.26. For local tasks an
answer can only change if the query touches the edit, so the answer-changing quota pulls the mention
rate up. A text-only model can exploit this, so the `mentions_edit == false` slice is pre-registered
(see the checklist) and must be reported next to the headline.

The cycle leaf-neighbour rule still reaches 79%: cycle accuracy below ~80% is not evidence of
cycle reasoning.

## Learned local shortcut (`scripts/analyze_v4.py --shortcut-only`)

The gate ceilings above are fixed lookup rules. A gradient-boosted classifier per task, fit on
static train with only one-hop features of the queried stations (degree, status, number of leaf
neighbours, smallest neighbour degree, closed neighbours, plus hop radius, graph size and closed
count), is much stronger. Results: `documents/experiments/results/v4_1-analysis/shortcut_ceilings.json`.

| Task | static test | test sessions (updated graph) |
|---|---|---|
| node_degree | 100.0 | 100.0 |
| cycle_membership | 89.9 | 82.2 |
| reachability | 87.1 | 83.0 |
| edge_exists | 84.6 | 81.4 |
| constrained_reachability | 62.4 | 60.4 |
| shortest_path | 41.2 | 37.4 |
| filtered_neighbor_count | 25.8 | 33.7 |
| within_hops_count | 16.2 | 16.8 |
| **non-attribute overall** | **63.4** | **61.9** |

What this means for the paper:

- A 3-layer GNN sees these features, so reaching ~63% on non-attribute tasks is consistent with a
  **local degree/status reader** and is not evidence of multi-hop reasoning. Reachability, cycle and
  edge existence are mostly solvable locally (v4.0 had the same problem: endpoint degree alone 72%,
  a small local lookup 84%); v4.1 did not change that, and the generator is frozen.
- The **shortcut-wrong slice** (1,510 of 3,960 non-attribute test turns where this classifier is
  wrong) is therefore the main evidence for graph use beyond local features. Report it for every
  model and condition.
- Counting tasks (`within_hops_count`, `filtered_neighbor_count`, `shortest_path`) are not locally
  solvable and separate a structure reader from a degree reader.

Test-session slice sizes: answer-changing 1,622; `mentions_edit == false` 2,220; both 359;
shortcut-wrong 1,510; 1,485 per paraphrase family.
