# GraphModi

GraphModi asks whether a graph language model (GLM) can keep answering correctly while a user
revises the graph in conversation. Each turn is a natural-language revision ("X is closed now")
followed by a question about the current network. GraphModi turns the revision into a typed edit
program, applies it to an explicit graph, re-encodes the graph into soft tokens, and answers with a
frozen Llama-3.1-8B-Instruct that never sees the revision text. Writing (did the edit land?) and
reading (can the model answer from the new tokens?) are scored separately.

**Current benchmark: metro_v4** ([`data/v4.py`](src/graph_modi/data/v4.py)). It fixes the October
2026 audit findings (cycle labels, shortcuts, sessions, write path). **v3 is frozen** for the
September/October numbers only; v3 and v4 are not comparable.

## Pipeline

```text
revision r_t ──► few-shot edit prompt (frozen Llama) ──► edit program  SET/ADD/DEL/NOOP ; ... END
                                                             │
G_{t-1} ──────────────────────────────────────────► executor ──► G_t
                                                             │
G_t ──► BERT-768 node text features ──► GraphSAGE (3 layers) ──► task-conditional readout
    ──► linear projector ──► 10 graph tokens ──► frozen Llama-3.1-8B-Instruct + question ──► answer
```

- **Write path.** A few-shot prompt (`TEAGLMBackend` in [`models/tea_glm.py`](src/graph_modi/models/tea_glm.py))
  produces an edit program; [`graph/edits.py`](src/graph_modi/graph/edits.py) parses it (multi-word
  station names supported) and [`graph/executor.py`](src/graph_modi/graph/executor.py) applies it.
  Invalid operations are skipped, so an edit error persists into later turns. Few-shot examples use
  the `direct` and `service` paraphrase families; `notice` is held out.
- **Read path.** Nodes are featurized by frozen `bert-base-uncased` over `label: attr=val, ...`
  ([`models/bert_tensorizer.py`](src/graph_modi/models/bert_tensorizer.py)), including `status`.
  Station `status` is withheld from the W(f_i) question text so open/closed travels only through
  the graph path. The readout is task-conditional (source/target node embeddings or mean pool),
  with a hop-radius scalar and a task one-hot before the linear projector.
- **Decoding** is greedy throughout.

## Benchmark (metro_v4)

Generated by [`data/v4.py`](src/graph_modi/data/v4.py), deterministic with seed 42.

- Ring core + pendant chains, 12–22 stations, three densities (mean degree 2.8 / 3.8 / 5.0) with
  diameter caps 7 / 6 / 5. CLEGR-style node and edge attributes; fictional two-word station names.
- Cycle queries only at degree 2; reachability / shortest path only with open endpoints.
- Answers drawn with per-task quotas (`BalancedSampler`); unique mode required for most-common.
- **Static QA:** 11 tasks. Training uses static graphs plus before/after counterfactual pairs.
- **Multi-turn grid:** 11 sizes × {1,2,4,8} lengths × 3 densities × 9 tasks = 1,188 sessions /
  4,455 turns per split. NOOP ≈ 17%; no net-noop / cancel / disconnecting edits.

Acceptance gates: [`scripts/audit_v4_gates.py`](scripts/audit_v4_gates.py) (43 pass / 0 fail).
Final independent audit: [`scripts/audit_v4_final.py`](scripts/audit_v4_final.py) (75 pass / 0 fail).
Notes: [`documents/experiments/benchmark_v4_2026-10-25.md`](documents/experiments/benchmark_v4_2026-10-25.md),
[`documents/experiments/benchmark_v4_final_audit_2026-10-25.md`](documents/experiments/benchmark_v4_final_audit_2026-10-25.md).

## Models

| | TEA-style | GraphToken-style | Soft prompt |
|---|---|---|---|
| Graph encoder | GraphSAGE 768/1024/1024, mean aggregation, dropout 0.5 | joint GNN + projector | none |
| Pretraining | contrastive InfoNCE (GNN must actually train) | none (random init) | none |
| Trained | linear projector to 10 × 4096 tokens | GNN + projector | 10 soft tokens |
| LLM | Llama-3.1-8B-Instruct, bf16, frozen | same | same |
| Training | 5 epochs, AdamW lr 1e-3, effective batch 24 | same | same |

## Evaluation conditions

Every condition runs on the same sessions ([`evaluation/runner.py`](src/graph_modi/evaluation/runner.py)).
v4 graph-model configs include `oracle_updated_graph`, `predicted_updated_graph`, frozen / shuffled /
question-only / history controls, `tool_solver`, and `majority_prior` (stale-answer baseline).

## Installation

Python 3.10+ and [uv](https://docs.astral.sh/uv/).

```bash
./scripts/setup.sh          # generation, evaluation, development dependencies
./scripts/setup.sh --tea    # adds PyTorch, Transformers, Accelerate for training/eval
```

Install the PyTorch wheel matching the server's CUDA driver if needed. Configs point `model.lm_name`
at a local Llama-3.1-8B-Instruct path (`/data/lmw/models/...`); change that for your machine.

## Reproducing a v4 run

Dataset JSONL is **gitignored**. Regenerate (or copy from a machine that has it) and check hashes
against `datasets/metro_v4/manifest.json`.

```bash
# 1. Data -> datasets/metro_v4/
uv run graph-modi generate --config configs/v4_data.yaml
# or: PYTHONPATH=src python3 scripts/audit_v4_gates.py --work datasets/metro_v4 ...

# 2. TEA: contrastive GNN pretraining, then the projector
uv run graph-modi pretrain-gnn    --config configs/v4_tea.yaml
uv run graph-modi train-projector --config configs/v4_tea.yaml

# 3. GraphToken (joint GNN) and soft prompt
uv run graph-modi train-projector --config configs/v4_graphtoken.yaml
uv run graph-modi train-projector --config configs/v4_soft_prompt.yaml

# 4. Static QA and multi-turn eval
uv run graph-modi static-eval --config configs/v4_tea.yaml --split test
uv run graph-modi evaluate --config configs/v4_tea.yaml
```

GPU run checklist (seeds, CIs, report slices): [`documents/experiments/v4_run_checklist.md`](documents/experiments/v4_run_checklist.md).

## Limitations

- **One seed until the GPU checklist is run.** Report mean ± spread over ≥3 seeds.
- **Shortcuts.** The 7-task degree+status ceiling is ~44%; models near that have not shown
  multi-hop reasoning. Cycle is degree-2 only; reachability still has a ~52% status-only ceiling.
- **Paraphrased edits.** Three families; `notice` is held out of few-shot. Edit accuracy is not
  free-form NL understanding.
- **Prompt formats.** Training uses the bare question; some eval conditions wrap
  `Question: ...\nAnswer:` and history conditions prepend revisions never seen in training.
- **GraphToken must train the GNN.** A frozen-TEA "GraphToken" is just a second TEA run.
