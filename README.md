# GraphModi

GraphModi asks whether a graph language model (GLM) can keep answering correctly while a user
revises the graph in conversation. Each turn is a natural-language revision ("X is closed now")
followed by a question about the current network. GraphModi turns the revision into a typed edit
program, applies it to an explicit graph, re-encodes the graph into soft tokens, and answers with a
frozen Llama-3.1-8B-Instruct that never sees the revision text. Writing (did the edit land?) and
reading (can the model answer from the new tokens?) are scored separately.

**Current benchmark: metro_v4** ([`data/v4.py`](src/graph_modi/data/v4.py)). It fixes the October
2026 audit findings (cycle labels, shortcuts, sessions, write path). **v3 is frozen** for the
September/October numbers only; v3 and v4 are not comparable.

## Pipeline

```text
revision r_t ──► few-shot edit prompt (frozen Llama) ──► edit program  SET/ADD/DEL/NOOP ; ... END
                                                             │
G_{t-1} ──────────────────────────────────────────► executor ──► G_t
                                                             │
G_t ──► BERT-768 node text features ──► GraphSAGE (3 layers) ──► task-conditional readout
    ──► linear projector ──► 10 graph tokens ──► frozen Llama-3.1-8B-Instruct + question ──► answer
```

- **Write path.** A few-shot prompt (`TEAGLMBackend` in [`models/tea_glm.py`](src/graph_modi/models/tea_glm.py))
  produces an edit program; [`graph/edits.py`](src/graph_modi/graph/edits.py) parses it (multi-word
  station names supported) and [`graph/executor.py`](src/graph_modi/graph/executor.py) applies it.
  Invalid operations are skipped, so an edit error persists into later turns. Few-shot examples use
  the `direct` and `service` paraphrase families; `notice` is held out.
- **Read path.** Nodes are featurized by frozen `bert-base-uncased` over `label: attr=val, ...`
  ([`models/bert_tensorizer.py`](src/graph_modi/models/bert_tensorizer.py)), including `status`.
  Station `status` is withheld from the W(f_i) question text so open/closed travels only through
  the graph path. The readout is task-conditional (source/target node embeddings or mean pool),
  with a hop-radius scalar and a task one-hot before the linear projector.
- **Decoding** is greedy throughout.

## Benchmark (metro_v4)

Generated by [`data/v4.py`](src/graph_modi/data/v4.py) (generator **v4.1**), deterministic with
seed 42. Frozen data: `datasets/metro_v4_1/` (hashes in its `manifest.json`).

- Ring core + pendant chains (some ending in a triangle), 12–22 stations, three densities (mean
  degree 2.8 / 3.8 / 5.0) with diameter caps 7 / 6 / 5. CLEGR-style node and edge attributes;
  fictional two-word station names.
- Cycle queries only at degree 2; reachability / shortest path only with open endpoints, also for
  counterfactual "before" items.
- Answers drawn with per-task quotas (`BalancedSampler`); unique mode required for most-common.
- **Static QA:** 11 tasks. Training uses static graphs plus before/after counterfactual pairs.
- **Multi-turn grid:** 11 sizes × {1,2,4,8} lengths × 3 densities × 9 tasks = 1,188 sessions /
  4,455 turns per split. NOOP ≈ 17%; 36% of turns change the answer (stale-answer baseline 63.6%);
  no net-noop / cancel / disconnecting edits.
- Shortcut ceilings: 7-task degree/status lookup 41.0%; cycle leaf-neighbour rule 79%.

Acceptance gates: [`scripts/audit_v4_gates.py`](scripts/audit_v4_gates.py) (45 pass / 0 fail / 2 warn).
Final independent audit: [`scripts/audit_v4_final.py`](scripts/audit_v4_final.py) (75 pass / 0 fail).
Note: [`documents/experiments/benchmark_v4_1_2026-10-30.md`](documents/experiments/benchmark_v4_1_2026-10-30.md)
(v4.0, superseded: [`benchmark_v4_2026-10-25.md`](documents/experiments/benchmark_v4_2026-10-25.md)).

## Models

Frozen v4.1 run recipe (configs generated by [`scripts/make_v4_configs.py`](scripts/make_v4_configs.py)):

| | GraphToken (main reader) | GraphToken warm start | Frozen random GNN | Soft prompt |
|---|---|---|---|---|
| Graph encoder | GraphSAGE 768/1024/1024, **sum** aggregation, dropout 0 | same | same, frozen at seeded init | none |
| Pretraining | none | contrastive InfoNCE, 10 GNN epochs | none | none |
| Trained | GNN (lr 1e-4) + linear projector (lr 1e-3) to 10 × 4096 tokens | same | projector only (lr 1e-3) | 10 soft tokens (lr 1e-3) |
| Schedule | 1 epoch, cosine, 200 warmup steps, val every 500 steps | 2 epochs, same | 1 epoch, same | 1 epoch, constant |
| Seeds | 42, 43, 44 | 42 | 42 | 42 |
| LLM | Llama-3.1-8B-Instruct, bf16, frozen | same | same | same |

All runs use effective batch 24 and chat-template-wrapped training prompts (`wrap_prompts: true`).
Mean aggregation, the earlier default, hides node degree and collapses (see `status_report_v3.md`
§0a). With sum aggregation the reader learns degree and status, and its accuracy is bounded by
the shortcut ceiling above. This is reported as a finding about the reader, not tuned away.

## Evaluation conditions

Every condition runs on the same sessions ([`evaluation/runner.py`](src/graph_modi/evaluation/runner.py)).
v4 graph-model configs include `oracle_updated_graph`, `predicted_updated_graph`, `structure_only`,
frozen / shuffled / question-only controls, `tool_solver`, `stale_answer` (pre-edit answer) and
`majority_answer` (per-task prior). Old names still load: `majority_prior` → `stale_answer`,
`cached_no_reencode` → `frozen_graph_history` (it was the same input). Result JSON records git SHA,
dirty flag, data sha256, checkpoint path and counts; per-turn rows are always written.

## Installation

Python 3.10+ and [uv](https://docs.astral.sh/uv/).

```bash
./scripts/setup.sh          # generation, evaluation, development dependencies
./scripts/setup.sh --tea    # adds PyTorch, Transformers, Accelerate for training/eval
```

Install the PyTorch wheel matching the server's CUDA driver if needed. Configs point `model.lm_name`
at a local Llama-3.1-8B-Instruct path (`/data/lmw/models/...`); the ladder script symlinks
`LM_PATH` there so the tracked configs stay unchanged.

## Reproducing the v4.1 runs

Dataset JSONL is **gitignored**. Copy `datasets/metro_v4_1/` from a machine that has it, or
regenerate it deterministically; the ladder script checks every sha256 against
`datasets/metro_v4_1/manifest.json` before training.

```bash
# Data -> datasets/metro_v4_1/ (CPU, ~10 min; also runs the acceptance gates)
PYTHONPATH=src python3 scripts/audit_v4_gates.py --work datasets/metro_v4_1

# The whole GPU ladder (setup, soft prompt, GraphToken s42, warm start, s43/s44, random GNN)
LM_PATH=/path/to/Meta-Llama-3.1-8B-Instruct scripts/run_v4_ladder.sh

# Or one run by hand
uv run graph-modi train-projector --config configs/v4_graphtoken_s42.yaml
uv run graph-modi static-eval --config configs/v4_graphtoken_s42.yaml --split test --checkpoint best
uv run graph-modi evaluate --config configs/v4_graphtoken_s42.yaml --checkpoint best

# Afterwards (CPU): shortcut audit, clustered CIs and the pre-registered slices
PYTHONPATH=src python3 scripts/analyze_v4.py --runs outputs
```

GPU run checklist (ladder, go/no-go, slices): [`documents/experiments/v4_run_checklist.md`](documents/experiments/v4_run_checklist.md).

## Limitations

- **One seed until the GPU checklist is run.** Report mean ± spread over ≥3 seeds.
- **Shortcuts.** The 7-task degree+status ceiling is ~44%; models near that have not shown
  multi-hop reasoning. Cycle is degree-2 only; reachability still has a ~52% status-only ceiling.
- **Paraphrased edits.** Three families; `notice` is held out of few-shot. Edit accuracy is not
  free-form NL understanding.
- **Prompt formats.** Training uses the bare question; some eval conditions wrap
  `Question: ...\nAnswer:` and history conditions prepend revisions never seen in training.
- **GraphToken must train the GNN.** A frozen-TEA "GraphToken" is just a second TEA run.
