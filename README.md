# GraphModi

GraphModi asks whether a graph language model (GLM) can keep answering correctly while a user
revises the graph in conversation. Each turn is a natural-language revision ("X is closed now")
followed by a question about the current network. GraphModi turns the revision into a typed edit
program, applies it to an explicit graph, re-encodes the graph into soft tokens, and answers with a
frozen Llama-3.1-8B-Instruct that never sees the revision text. Writing (did the edit land?) and
reading (can the model answer from the new tokens?) are scored separately.

This branch contains only the current **v3** benchmark and its runs: BERT-768 node features and
yes/no labels balanced 50/50. Earlier experiments are in git history on the `exact2x` branch.

## Pipeline

```text
revision r_t ──► few-shot edit prompt (frozen Llama) ──► edit program  SET/ADD/DEL/NOOP ; ... END
                                                             │
G_{t-1} ──────────────────────────────────────────► executor ──► G_t
                                                             │
G_t ──► BERT-768 node text features ──► GraphSAGE (3 layers) ──► task-conditional readout
    ──► linear projector ──► 10 graph tokens ──► frozen Llama-3.1-8B-Instruct + question ──► answer
```

- **Write path.** A few-shot prompt (`TEAGLMBackend` in [`models/tea_glm.py`](src/graph_modi/models/tea_glm.py))
  produces an edit program; [`graph/edits.py`](src/graph_modi/graph/edits.py) parses it (multi-word
  station names supported) and [`graph/executor.py`](src/graph_modi/graph/executor.py) applies it.
  Invalid operations are skipped, so an edit error persists into later turns.
- **Read path.** Nodes are featurized by frozen `bert-base-uncased` over `label: attr=val, ...`
  ([`models/bert_tensorizer.py`](src/graph_modi/models/bert_tensorizer.py)). The readout is
  task-conditional: when the question names a source/target station it uses those node
  embeddings and zeroes the pooled slot, otherwise the mean pool; a hop-radius scalar and a task
  one-hot are appended before the linear projector. As in CLEGR, the text of the queried node(s),
  W(f_i), is added to the question.
- **Decoding** is greedy throughout.

## Benchmark (v3)

Generated by [`data/v3.py`](src/graph_modi/data/v3.py), deterministic with seed 42.

- Compact subway graphs, 12-22 stations, three densities (mean degree 2.8 / 3.8 / 5.0) with the
  diameter capped at 7 / 6 / 5. CLEGR-style node attributes (accessibility, architecture,
  cleanliness, music, size, line) and edge line attributes; fictional two-word station names.
- Station `status` stays in the graph but is withheld from W(f_i), so it cannot be read from the
  question text.
- Answers are drawn with per-task quotas (`BalancedSampler`): every yes/no task is 50/50 within
  every prompt-visible stratum.
- **Static QA:** 11 tasks (edge existence, reachability, constrained reachability, cycle
  membership, node degree, filtered neighbor count, shortest path, within-hops count, most common
  attribute within hops, attribute lookup, attribute check). Training uses static graphs plus
  before/after counterfactual pairs; no model is trained on multi-turn sessions.
- **Multi-turn (exact2x) grid:** 11 graph sizes x session lengths {1, 2, 4, 8} x 3 densities x 9
  tasks = 1,188 sessions / 4,455 turns per split. On test, 41% of turns change the answer and 37%
  are NOOP turns.

## Models

| | TEA-style | GraphToken-style | Soft prompt |
|---|---|---|---|
| Graph encoder | GraphSAGE 768/1024/1024, mean aggregation, dropout 0.5 | TEA's pretrained GNN | none |
| Pretraining | symmetric InfoNCE between GNN node embeddings and the LLM's token embeddings of each node's text (10 epochs) | uses TEA's | none |
| Trained | linear projector to 10 x 4096 tokens | projector (see limitations) | 10 soft tokens |
| LLM | Llama-3.1-8B-Instruct, bf16, frozen | same | same |
| Training | 5 epochs, AdamW lr 1e-3, effective batch 24, seed 42 | same | same |

## Evaluation conditions

Every condition runs on the same sessions ([`evaluation/runner.py`](src/graph_modi/evaluation/runner.py)).

| Condition | Graph tokens | Prompt text |
|---|---|---|
| `oracle_updated_graph` | gold current graph G_t, re-encoded every turn | question |
| `predicted_updated_graph` | graph built from the model's own edit programs, re-encoded | question |
| `structure_only` | initial graph G_0, never updated | question |
| `frozen_graph_history` / `cached_no_reencode` | G_0 (identical inputs in this backend) | revision history + question |
| `graph_once_then_text` | G_0 on the first turn only | revision history + question |
| `shuffled_graph` | another session's G_0 | question |
| `question_only` | none | question |
| `token_matched_history` | none | last 64 words of history + question |
| `soft_prompt` | learned prompt, no GNN | revision history + question |
| `majority_prior` | no model: returns the pre-edit answer (the *stale-answer* baseline) | |
| `tool_solver` | no model: symbolic solver on the gold graph (sanity ceiling, 100%) | |

The per-task majority predictor (each task's most common gold answer) is a reference point computed
from the data, not a runtime condition.

## Installation

Python 3.10+ and [uv](https://docs.astral.sh/uv/).

```bash
./scripts/setup.sh          # generation, evaluation, development dependencies
./scripts/setup.sh --tea    # adds PyTorch, Transformers, Accelerate for training/eval
```

Install the PyTorch wheel matching the server's CUDA driver if needed. The v3 configs were run on
48 GB L40 GPUs and point `model.lm_name` at a local copy of Llama-3.1-8B-Instruct
(`/data/lmw/models/...`); change that path for your machine.

## Reproducing a v3 run

```bash
# 1. Data: static train/val/test, counterfactual pairs and exact2x sessions -> datasets/metro_v3/
uv run graph-modi generate --config configs/v3_tea.yaml

# 2. TEA: contrastive GNN pretraining, then the projector
uv run graph-modi pretrain-gnn    --config configs/v3_tea.yaml
uv run graph-modi train-projector --config configs/v3_tea.yaml

# 3. GraphToken (reuses outputs/v3_tea/gnn) and the soft prompt (no GNN)
uv run graph-modi train-projector --config configs/v3_graphtoken.yaml
uv run graph-modi train-projector --config configs/v3_soft_prompt.yaml

# 4. Static QA -> outputs/<run>/static_eval_<split>.json
uv run graph-modi static-eval --config configs/v3_tea.yaml --split test

# 5. Multi-turn grid -> outputs/<run>/evaluation.json  (predfix configs add model-written edits)
uv run graph-modi evaluate --config configs/v3_exact2x_tea.yaml
uv run graph-modi evaluate --config configs/v3_exact2x_tea_predfix.yaml

# 6. Aggregate by task / density / size / session length / turn
python scripts/analyze_exact2x.py outputs/v3_exact2x_tea/evaluation.json datasets/metro_v3 \
    documents/experiments/results/v3-20260929/exact2x_tea_analysis.json
```

Committed summaries live in `documents/experiments/results/v3-20260929/` (static results as
`static_<model>_<split>.json`, multi-turn as `exact2x_<model>[_predfix]_analysis.json`) and
`results/v3x-20260929/` for the TEA variants (`configs/v3x_*.yaml`: 3-epoch checkpoint, deeper GNN,
MLP projectors, 3x data). From those files:

```bash
python scripts/make_figures_v3.py      # documents/experiments/figures/v3_*.png, v3x_variants.png
python scripts/build_report_v3.py      # documents/experiments/status_report_v3.md
python scripts/make_report_figures.py  # documents/experiments/figures/report/{tea,graphtoken}/
```

`run-session --config ... --session <file.jsonl> --index N` prints one session turn by turn.

## Limitations

- **One seed.** An identical recipe varies by about 4 points between runs, so single-seed gaps of
  2-4 points are not interpretable.
- **GraphToken-style is not yet a separate method.** `train_graph_token` unfreezes the GNN but
  `train_projector` re-freezes it and optimises only the projector, starting from TEA's GNN. The
  GraphToken runs are a second TEA training run; TEA-vs-GraphToken differences are run variance.
- **Templated revisions.** Node edits use one template and edge edits are the edit command itself,
  so edit accuracy overstates free-form performance.
- **Shortcuts.** Reachability largely reduces to the queried endpoint's hidden status; the
  stale-answer baseline scores 59% because 59% of turns keep their pre-edit answer.
- **Prompt formats.** Training uses the bare question; inference wraps it in
  `Question: ...\nAnswer:`, and no training example contains revision history, which handicaps the
  history-text conditions.
